#### 6.10 Product/Spec amendments for the move to production

Where the concept goes beyond v1's public contract (`docs/spec/06-interfaces-and-contracts.md`, "Public read":
schema version 2 carries open/closed with the next opening, freshness `fresh | stale | unavailable | closed`, band,
count floored at 0, last-updated, source, computed-at and a `trend` that is always null; no capacity, denominator,
percentage or history). Each row is an amendment **to propose**, not a decision: nothing here authorizes
implementation, and each needs its own versioned Product/Spec change first.

| Id | L | Entry |
| --- | --- | --- |
| AMD-P1 | P | **The percentage of capacity** («**58%** من السعة» / "**58%** full", PUB-10, PUB-70). Schema version 2 neither accepts nor emits `capacity`, a denominator or `percentFull`, and TRU-6 says nothing is a percentage of capacity; the contract's post-v1 reservation records the feature as approved in principle (06, "Public capacity boundary", public-redesign-r01 DECISIONS item 4): when built, on by default with no warning, and omitted when the owner turns it off (the concept's ?pct=off). **Production needs first:** a new versioned public API with an optional percentage the server alone decides to send; an owner-only setting, audited (actor, prior and new value, time); the field omitted entirely while disabled; TRU-6 and SPEC's acceptance criterion 2 amended to match. The page shows the count and the percentage side by side, which together reveal capacity; the reservation's own text says the owner accepts that. |
| AMD-P2 | P | **The usual day** (6.3: a typical-day curve per weekday, every opening hour's usual inside, from past weeks; the week row to reach any day). Schema version 2 carries no history; the contract reserves a curve for a later version and records it as approved in principle (06, "Public typical-day curve", DECISIONS item 3). **Production needs first:** a new versioned API carrying one aggregate curve per weekday, computed on the server from history, with no per-visitor data and no capacity, denominator or ratio. The page also needs, which the reservation does not yet name: (a) each weekday's **opening hours** (the card's «مفتوح 1 م – 1 ص», the bars' span, Closed's quietest hour; v2 sends only the next opening, and only when closed); (b) **a level for each usual hour**, because the page words every usual hour («مزدحم عادةً») and the concept bands the usual count by fixed counts on a room it never shows (`band`, `public.js:118`; PUB-122), which production cannot do without capacity; the band must come from the server, as LVL-1 has the historical band read from the row; (c) **the basis** of the curve (how many weeks; what happens on a new gym, a holiday or an hour with too few days, TRU-2), which the page does not show yet; (d) the bar scale (PUB-3) from the curve's own maximum, never from capacity. |
| AMD-P3 | P | **Now against the usual** (the comparison «أعلى من المعتاد» / "Busier than usual", PUB-11; the quietest time left held against now, PUB-18; the grain's flow, PUB-48). v2's `trend` is reserved and always null; the concept compares the live count with this hour's usual (thresholds 0.6, 0.9, 1.1, 1.4; within a tenth for "now or later") on the client. **Production needs first:** the comparison's rule written into SPEC (where it is computed, client or server; its thresholds; TRU-5's clear-difference rule, which the page's "About usual" within ±10% departs from, PUB-118), the curve of AMD-P2 for this hour, and a rule for the hour now stands in when the count is stale (the page drops the comparison in every state but Live, PUB-34). |
| AMD-P4 | P | **The count's wording** («نحو **70** في الصالة» / "About **70** inside", PUB-69). SPEC sends an approximate count, floored at 0; GLO-2's words for it are «داخل الصالة الآن · تقريبًا» / "Inside now · approx.", with "an exact headcount" to avoid. The page says the approximation in «نحو» / "About" so the count and the percentage hold one line down to 360 px (A39). **Production needs first:** GLO-2 amended to allow this form on the public page (or the page brought to GLO-2's), and SPEC's count semantics (floored at 0; GLO-6's genuine zero, «الصالة خالية · 0», which the page has no wording for yet) carried into the public copy. |
| AMD-P5 | P | **The concept label** («مفهوم استكشافي · بيانات افتراضية» / "Exploration concept · synthetic data", PUB-4, PUB-65, PUB-117) and the concept description in `<meta name="description">`. GLO-15 says no Eclipse screen carries one; the concept keeps it because its data are synthetic. **Production needs first:** neither, on any screen or in the document's description; the page's title and description in the visitor's language (PUB-133). |
| AMD-P6 | P | **The page's controls and states against SPEC's route.** SPEC's `/` "carries the brand, … the language switch, and in the error state only «إعادة المحاولة»". The concept adds the hours (buttons, PUB-19 to PUB-21), the step keys where an hour is under 24 px (PUB-134; fixes-43) and the week row (PUB-27), each reachable by Tab in every state that shows it, and in Loading and Error the week row's picked key stays a Tab stop while it waits (PUB-127). **Production needs first:** the route's description amended for the usual day's controls (with AMD-P2), and a decision whether Error's only control is the retry (the week row then leaves the tab order while it waits). Already covered by v2, for the record: Live, Delayed (`stale`, with last-updated for the absolute time and the age), Unavailable and Closed (with the next opening) map onto `freshness`; Loading and Error are the client's. Not yet written by the concept: Closed after closing (the next opening on another day, «يفتح السبت 8 ص»), and a polled change between Live, Delayed and Unavailable within one visit (PUB-128; the head already holds still for every level, PUB-38). |

### 6.12 The code against the notes

round's `COPY.md` (A39). Where they and the code disagree, the code wins, and the rows above say what the code does.

it fixed (the head held for one level, the plain spaces, the stale comments about Unavailable's word, one line of
facts, straight-line sizes and the fold). final-fixes-45 wrote no notes either; its rows are marked so, and it removed
from 6.11 what it fixed (PUB-138, the air after a held comparison) and rewrote PUB-131 to what still steps.
