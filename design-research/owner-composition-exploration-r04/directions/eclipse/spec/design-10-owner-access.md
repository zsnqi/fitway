The code field's own messages (FLD-4, on the page, before anything is sent): «اكتب الرمز» / "Enter the code";
«استخدم حروفًا إنجليزية وأرقامًا فقط» / "Use only English letters and digits" (a space, a symbol or an Arabic letter);
«اكتب 8 أحرف أو أرقام على الأقل» / "Use at least 8 letters or digits". Arabic-Indic digits typed become Western digits
as they are typed (NUM-1), so they are never refused. A code the server finds malformed (only if the page's check was
bypassed) falls to the failure sentence, as `staff_pin_shape` does (`apps/web/src/hooks/use-owner-access.ts`).

**Synthetic history.** Omar Alharbi's creation (10 January 2026, id 1001) and deactivation by فهد (1 February 2026, id 1002) are older than the card's eighth record. The original records keep ids 1-56; Access's changes start at 57 and skip those two reserved ids. With `record=<id>`, the log loads through that record, brings it into view, marks it with the existing inset focus treatment and `aria-current`, and focuses it for keyboard and assistive technology. An unknown id shows the access records with «هذا السجل غير موجود في هذه العينة.» / "This record isn't in this sample." and focuses that sentence. Record links carry Access's `case=long|short` name fixtures, and only arrivals with `record=` use those same stored-name samples on Activity log. Filtering clears the arrival; opening without `record=` keeps its existing behavior.
