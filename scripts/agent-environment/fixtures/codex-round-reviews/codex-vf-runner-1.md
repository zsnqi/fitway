1. **V1.** **Literal reading:** Prove the loading predicate, take the capture, then separately prove the loaded predicate; the brief never requires those predicates to be mutually exclusive or tied atomically to the captured frame. **What goes wrong:** The loading proof can pass just before capture, then the payload can arrive before or during screenshotting, so a post-change frame is accepted as the loading state, precisely what V1’s intent forbids. **Close it:** Require the phase to be frozen during capture or require before/after phase tokens bracketing one capture with an explicit rejection when a transition crosses those bounds.

2. **V1.** **Literal reading:** “That item” can be handled by matching only Reports’ `arrive=500` plus `state=loading`, while retaining the old behavior for every other item. **What goes wrong:** The named self-compare can pass, but other arrival or time-changing states still fail; the goal of capturing changing states generally and the intent that “an arrival can be checked like any other state” remain unmet. **Close it:** Require a general transition mechanism plus at least one additional planted changing-state item that must pass the same proof.

3. **L1.** **Literal reading:** Existing tests can keep every assertion call and test count while a shared assertion helper, setup, or mock under the permitted skill tree is changed to weaken or bypass those assertions; `fast` then passes and L2’s clean-status check still succeeds. **What goes wrong:** The suite runs but no longer protects today’s behavior, so regressions outside the new checks can ship despite L1 being reported as PASS. **Close it:** Add that no existing assertion helper, predicate, setup, or mock may weaken the tests, and the committed production code must be exercised directly.

4. **V3.** **Literal reading:** The non-CLI exception can be implemented by recognizing a tool name without resolving which executable actually receives the option, so a fake CLI option placed after a wrapper or documented non-CLI command is exempted. **What goes wrong:** A reader can still encounter a nonexistent CLI option in `SKILL.md`, while the test reports that the whole guide is covered. **Close it:** Resolve command wrappers to the final executable and exempt only options bound to a documented non-CLI executable; all other option tokens must be checked against the CLI.

5. **V2.** **Literal reading:** The drift requirement can be satisfied by a test that calls a replacement helper with a synthetic missing string, while the live speed test retains its separate silent `.replace` of `baseline-cache.mjs`. **What goes wrong:** The helper test fails correctly, but a later change to the real cache-root line still leaves the actual test path silently unreplaced, reproducing F168’s collision risk. **Close it:** Require the drift test to exercise the real `baseline-cache.mjs` text through the exact setup path used by the speed test and assert the observed process cache path.
