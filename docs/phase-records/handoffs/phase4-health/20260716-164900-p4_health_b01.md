## Goal and acceptance

Deliver the frozen Phase 4 operational-health backend: the persisted `edgeCurrentHealth`
projection, the freshness/condition evaluator, and the authenticated
`staff.operationalSnapshot` procedure, exactly per `SPEC.md` 414–457. This slice is
backend-only and must not implement `/login`, `/staff`, or `/admin` UI, and must not touch
Phase 8 transition/alert history.

Acceptance requires tests proving:

- migration `0003` adds one `edgeCurrentHealth` projection keyed by device with exactly
  `deviceId`, `sequence`, `processStatus`, `cameraStatus`, `feedStatus`, `detectorFps`,
  `edgeObservedAt`, `receivedAt`, `updatedAt`; statuses are `ok | degraded | failed |
  unknown`; `detectorFps` is a finite non-negative number or `null` (`null` means unknown,
  not zero); no seed rows — existing devices are `unavailable` until their first accepted
  post-migration live push;
- the projection is written only for an accepted contiguous live push, in the same database
  transaction as minute upserts, current-state update, device sequence advancement, and
  `lastSeenAt`;
- replay, sequence gap, validation failure, disabled device, and transaction rollback leave
  the projection byte-for-byte unchanged (backfill remains out of scope and must not gain a
  write path);
- freshness is `current` when trusted `receivedAt` age is strictly below the settings-driven
  `operationalStaleAfterSeconds`, `stale` at equality and beyond, and `unavailable` when
  there is no projection, no usable active device, or a disabled device — with all raw
  fields/times null except an independently known `lastSeenAt`;
- condition precedence for a usable projection is any `failed` → `failed`, else any
  `degraded` → `degraded`, else any `unknown` → `unknown`, else `healthy`; stale freshness
  never erases last-known flags; transport/API failure is an error state and is never
  converted into `unavailable` current health;
- `staff.operationalSnapshot` returns exactly the frozen DTO: the ten-field `health` block,
  plus `schemaVersion`, `computedAt`, the public occupancy fields, authorized `capacity`,
  and source detail — and reserves no speculative Phase 5 command fields;
- the leaf accepts `staff | owner` through the integrated auth guards with exact `401`
  (missing/expired authentication) and `403` (valid wrong role) behavior;
- public payload schema v2 remains completely free of capacity, percentage, health, device
  identity, and history;
- a real HTTP/disposable-Postgres integration test at
  `apps/server/src/phase4-health.integration.test.ts` covers the accepted push → projection
  → snapshot path and the non-mutation cases.

The edge wire format is frozen: `edgePushRequestSchema` already validates the required
`health` fields, the response schema does not change, and no OpenAPI, Python fixture, or
simulator change is authorized. The server/evaluator owns freshness and condition, the
repository owns projection reads, and no consumer recomputes them. A new dependency or any
manifest/lockfile change is outside the lease and requires coordinator approval.
