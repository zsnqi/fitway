## Configuration and privacy contract

The strict JSON config is schema version 1 and rejects unknown keys. It contains:

- `endpoint.baseUrl`, resource path, request timeout, and TLS requirement outside loopback
  development. The resource path must be the frozen external `/api/edge/push`; internal
  `/edge/push` is valid only when the base URL is loopback. URL joining is deterministic and tests
  assert the exact resulting URL without permitting path, query, or fragment injection;
- `credentials.tokenFile`, resolved relative to the config file, readable and non-empty with at
  least 32 bytes; the raw token never enters normalized config display/log output;
- `state.sqlitePath`, resolved relative to the config file, and fixed retention `48` hours;
- `source.kind: "synthetic"`, seed, mode, initial count, and sample interval;
- process cadence/backoff bounds used only until server acknowledgement settings supply the accepted
  push interval.

The config may retain opaque site-calibration fields for future RTSP/ROI/line/threshold/FPS input,
but b01 runtime accepts only `source.kind: "synthetic"` and returns a named site-gate error for
`rtsp`; it never opens a stream or imports CV code. URLs are redacted to scheme/host category in
diagnostics; user info, query, fragment, token, payload, exact file content, and RTSP details are
never logged.

## SQLite and state-machine contract

Use Python stdlib `sqlite3`; no manifest change. Initialize with WAL, `synchronous=FULL`, foreign
keys on, and an explicit application/user schema version. A singleton state row holds sequence,
count, current minute/entries/exits, applied command ID, and exact canonical `last_request` /
`in_flight_request` BLOBs. An outbox table uses canonical minute start as its primary key and stores
only aggregate count/entries/exits. No raw crossing events, frames, image paths, identities, health
history, tokens, or credentials are stored.

Every public mutation uses `BEGIN IMMEDIATE` and one commit:

- a sample finalizes/upserts the prior minute, resets the accumulator, floors count at zero, and
  deletes only oldest rows beyond 2,880;
- preparing returns the existing valid in-flight body bytes byte-for-byte plus parsed, correlated
  request metadata; otherwise it builds the next 100-minute backfill or live request through the
  extracted canonical protocol, persists those canonical bytes before returning them, and does not
  update `last_request`;
- while any request is in flight, each sample still atomically updates count, current-minute
  accumulator, rollover, and outbox without changing the frozen in-flight BLOB. Later settlement
  deletes only the minute keys enumerated by the correlated durable request, so minutes accumulated
  after prepare survive;
- settling validates/correlates acknowledgement against the durable in-flight request before any
  mutation. Processed/replay advances sequence and deletes exactly the request's backfill minutes.
  `commands_pending` applies ascending new commands, persists count/applied ID, and replaces the
  same-sequence live in-flight bytes before any resend;
- `last_request` changes only on a correlated processed/replay settlement, never on prepare,
  sampling, retry, or invalid acknowledgement;
- invalid/cross-version/mismatched acknowledgement, corruption, serialization failure, or injected
  commit failure leaves sequence/count/applied ID/outbox/last/in-flight byte-identical.

Database busy/corruption fails closed with a category diagnostic and nonzero process exit; it never
silently recreates or discards state. Document operator backup/restore of the SQLite DB plus WAL/SHM
only while the runtime is stopped.

## Runtime and transport contract

Extract canonical validation, serialization, acknowledgement correlation, command application, and
request construction from `simulator.py` into `fitway_edge.protocol`; keep the simulator CLI and all
18 tests behavior-identical by importing the shared module.

`EdgeRuntime` owns one store/source/transport. It samples synthetic directional deltas, finalizes
minutes, prepares/persists before send, and uses the existing server acknowledgement cadence. The
production transport accepts and sends the exact durable body bytes as `application/json`; it may
parse the correlated metadata for validation but must never serialize that object again. A captured
first HTTP body and the restart replay body must equal the SQLite BLOB and each other byte-for-byte.
Network/5xx/429/invalid-response cases keep the exact in-flight request and bounded backoff; 401/403
stops with an authentication category. Backfill drains before live; `commands_pending` corrects and
resends the same live sequence; only a correlated processed/replay acknowledgement settles.
SIGINT/SIGTERM closes source/store cleanly. Abrupt termination is recovered solely from committed
SQLite state. Logs are fixed event/category names with timestamps and aggregate health only.

## Windows lifecycle contract

Keep config, token, SQLite, and logs under a configurable `%ProgramData%\FITWAY` root separate from
immutable versioned program directories. `install.ps1` validates absolute paths for the Python
executable, stable watchdog script, current-version pointer, configuration, and data root plus a
caller-supplied least-privilege principal. It provisions and verifies ACLs so only Administrators,
SYSTEM, and that principal can read the token/config and the principal has only the data/log access
needed at runtime. It renders the exact boot-triggered Scheduled Task plan under `-PlanOnly`, and
only installs when explicitly invoked by an administrator on the target PC. The task identity,
logon mode, least run level, absolute action/arguments, restart policy, and single-instance policy
are explicit; no action depends on `PATH`, Python launcher registration, or current directory. No
token, password, payload, or RTSP URL appears in task arguments or plan output.

`run.ps1` is the watchdog: from its explicit absolute arguments it resolves a single current-version
manifest to one immutable version directory, launches the absolute Python executable and absolute
`edge/client.py --config <absolute-path>`, holds an exclusive singleton lock, propagates stop to the
entire child process tree, restarts unexpected exits with bounded delay, and prevents a hot restart
loop. `uninstall.ps1` deterministically stops that process tree, removes only the exact named task,
and preserves config/token/state/logs unless a separate explicit data-removal action is approved.

The update runbook is stop/disable -> checkpoint and back up the stopped SQLite DB with its WAL/SHM
as one recovery unit -> stage an immutable version directory -> run self-tests/config/schema
compatibility checks -> write and flush a temporary current-version manifest -> atomically replace
the single manifest -> enable/start -> verify heartbeat. Each release declares its supported SQLite
application versions; startup refuses an unsupported newer schema, and any migration is one
transaction. If the old version still supports the resulting schema, rollback atomically restores
the old manifest; otherwise rollback stops the runtime and restores the complete stopped backup
before restoring the old manifest. No mutable in-place program update or automatic remote updater.

CI never registers a real task. Plan-only tests assert the exact principal, logon mode, run level,
task name, boot trigger, single-instance/restart settings, absolute action and arguments, current
manifest/config paths, cwd independence, ACL operations, and absence of token/password/RTSP values.
It runs the watchdog against disposable child process trees that fail/restart/stop while sharing a
temporary SQLite path and proves no orphan remains.
