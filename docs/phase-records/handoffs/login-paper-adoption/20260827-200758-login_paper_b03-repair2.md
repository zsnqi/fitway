### Environment note (evidence, not an excuse)

The first `pnpm verify:fast` invocation went red in the Python simulator lifecycle tests
(`test_windows_lifecycle.py`: sqlite "no such table: starts", "the disposable client never
started", 3 failures + 2 errors), reproducible standalone at the same commit. Diagnosis: the
lifecycle tests create their disposable trees under `%TEMP%` (`C:\Users\Pc Force\...`), and
`edge/windows/run.ps1` launches the supervised client with `Start-Process -ArgumentList`
(Windows PowerShell 5.1), which does not quote arguments containing spaces, so the client path
splits at the space in the user profile (`python: can't open file 'C:\Users\Pc'`). Evidence that
this is pre-existing and independent of the candidate: (a) `edge/` is byte-identical from base
`0ef72c2` through this candidate (run.ps1 unchanged since `26f8e30`); (b) with `%TEMP%` redirected
to a space-free directory the full simulator suite passes **117/117 OK in 25.6s** at this exact
candidate; (c) the failure mechanism is in `run.ps1` argument quoting vs the machine's user
profile, reachable at any commit on this machine. The register has no entry for this (and none may
be opened during a red run), so it is recorded here as an environment-dependent red with its
mechanism, and the green ladder was taken with `%TEMP%=C:\fwtmp-nospace` (removed afterwards).
**Finding for the coordinator (out of this slice's owned paths, not fixed here):**
`edge/windows/run.ps1` line 157 quotes nothing around `$clientScript`/`$ConfigPath`; any install
location or data root containing a space will break the real edge client the same way the tests
break. This is a product-surface defect worth its own slice.
