# owner-design-exploration-r02 — human rejection and diagnosis

The user reviewed all four r02 concept directions and rejected every one. They found them visually similar and disliked the colors, forms, ordering, and chart treatments. They then clarified the intended target: the running Owner interface has an overall style they like, and the next redesign should stay approximately within that style while addressing its problems. No r02 concept is selected, accepted, or a future visual reference. Production, canonical frames, Paper, and Owner visual-authority status are unchanged.

## Evidence reviewed

The coordinator personally inspected all four concept directions' English and Arabic populated 1440×900 and 390×844 frames, then the fresh running local synthetic demo's Owner Daily page in both languages at those exact sizes and full-page mobile. A separate repository inspector prepared the live demo using `docs/desktop-demo.md`: separate `fitway_desktop_demo` database, real local Owner authentication, loopback web and API, no production credentials or tracked source changes. Current-session captures are under ignored `.local/demo/owner-inspection/`; they are diagnostic evidence, not accepted authority. A fresh reviewer inspected the concept frames independently and confirmed the repeated visual family.

The running current page has the near-black/oxblood atmosphere, translucent rail, rounded integrated analytics board, and FITWAY red chart line that the user wants to keep in spirit. In the observed mobile opening viewport, the three vertically stacked metrics push the chart low, and the horizontal Owner section navigation crops later destinations without an obvious continuation cue. The graph needs a clearer first-read explanation; the visible coverage percentage is small and lacks its denominator in the closed view. These are concrete review targets, not approval of any particular replacement.

## Cause and corrective direction

No evidence points to corrupt design files or an unavailable design engine. `pnpm check:design-context` failed under the read-only sandbox's child-process restriction and passed with child-process permission using Impeccable 4.0.0. The four concepts render coherently. The r02 packet told all authors to start from the same dark/red foundation and current-state/day-record story, while requiring only one meaningful difference in composition, material, information order, or interaction. It also treated incumbent production recipes and prior Owner topology as anti-ruts. Independent authors consequently varied page theses but converged on near-black surfaces, Cairo, red hairlines/curves, and similar state-to-history flow. The coordinator did not run an early side-by-side visual-distinctness or taste check before full implementation; a later “no blocker for comparison” review was insufficient to judge appeal. This was a search-brief and review failure, not a case for blaming a broken repository or the model alone.

For a successor, inspect the current page and preserve its visual character as a positive reference. Name specific problems in its hierarchy, mobile navigation, metric density, chart explanation, and state/coverage copy before proposing replacements. Test early first-screen and chart treatments with the user before building whole pages; each option should make an observable choice in information order, shape, rhythm, and chart grammar while keeping the chosen FITWAY visual anchors. The task sets its own direction count. No global policy file is changed by this record; the separate one-writer and generic direction-count policy suggestions remain for later review.

The r02 milestone is stopped as `NEEDS_HUMAN` with accessibility and perceptual gates pending. A new design task requires a revised task packet and scoped authorization; no unselected r02 concept advances to production.
