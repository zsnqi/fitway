# Product-wide focus-visibility gap — recorded, not yet scheduled

- Recorded: 2026-08-15 03:15 +03:00.
- Origin: surfaced by the `phase11-shell` b02 worker as an out-of-scope observation, then
  **independently confirmed by the coordinator** against `main` rather than taken on report.
- Status: no slice authorized yet. This record exists so the finding is not lost between phases.

## The two gaps

Coordinator evidence, run on `main` at `888f4d3` before the shell candidate merged:

```
grep -rl "forced-colors" apps/web/src/            -> no match
apps/web/src/components/staff/staff.css:205       -> .operations-skip-link:focus-visible
apps/web/src/index.css:132                        -> .public-skip-link:focus-visible
```

1. **No high-contrast focus indicator outside the incoming owner shell.** `apps/web/src` contains no
   `@media (forced-colors: active)` block at all. The ordinary FITWAY focus treatment is a
   `box-shadow` ring with `outline: 0`, and forced-color adjustment discards `box-shadow`. So in
   Windows high-contrast mode, focused controls on `/`, `/staff`, and `/login` have no visible
   indicator. The owner shell is the first surface to carry a compensating outline, and only because
   `phase11-shell` tests for it.

2. **Skip links that stay off-screen while focused.** Both remaining skip links scope their reveal
   to `:focus-visible`. `:focus-visible` tracks interaction modality, so after any pointer
   interaction a focused skip link stays at its parked offset — focus moves somewhere invisible.
   `DESIGN_GUIDE.md` §13 requires "a visible-on-focus skip link" and that "focus is never hidden".

Both gaps are the same root cause the `phase11-shell` b01 attempt died on. b01's record described it
as one failing target; the b02 investigation established the loop was aborting on its first
iteration and that every visible enabled target in that shell was affected. The same reasoning
applies to the surfaces that were never tested for it.

## Third gap, added after independent verification of `phase11-shell` b02

3. **The owner skip link ignores reduced motion.** Found by the `phase11-shell` b02 **verifier**,
   independently and not reported by the implementer.
   `apps/web/src/components/owner/owner-shell.css:57-58` selects
   `.owner-shell .operations-skip-link` at specificity `0,2,0`, which outranks the reduced-motion
   block's `.owner-shell *` at `0,1,0`, so its `transition: none` never applies. Measured: the skip
   link is the only element inside `.owner-shell` retaining a real transition under
   `prefers-reduced-motion: reduce`, travelling `top` −62.4 → −8.1 → 6.9 → 8 over roughly 160 ms
   instead of appearing at once.

   Nothing catches it because the spec's reduced-motion assertion checks `.owner-rail`, which
   correctly reports `0s`. It is inherited from the b01 candidate and was not introduced by the b02
   change. `DESIGN_GUIDE.md` §10 sanctions short property-specific focus transitions and scopes its
   reduced-motion clauses to charts and skeletons, so this is not a contract violation — but it
   defeats the component's own declared intent. The fix is to include `.operations-skip-link` in the
   reduced-motion block at equal or higher specificity.

   It was **not** patched into the verified candidate. Amending code after an independent PASS
   would break the chain between what was verified and what was integrated, for a non-blocking
   finding. It belongs to this slice instead.

## Why this is not folded into an existing slice silently

`staff.css` and `index.css` are shared surfaces owned by earlier, already-`DONE` milestones. Editing
them from the shell slice would have been unleased shared-file work, and the b02 worker correctly
declined. Equally, marking those milestones `DONE` did not license leaving a known accessibility
defect unrecorded.

## Scope when it is scheduled

Two files and their focused browser evidence:

- `apps/web/src/index.css` — public skip link, and a forced-colors focus block for the public
  surface.
- `apps/web/src/components/staff/staff.css` — the `/staff`, board, and login shells' skip link, and
  a forced-colors focus block for their interactive targets.
- `apps/web/src/components/owner/owner-shell.css` — the reduced-motion specificity fix in gap 3.

`/login` additionally has its own composition arriving with `login-paper-adoption`; whichever of the
two lands first must not leave the other inconsistent. The natural sequencing is to fold the login
surface's forced-colors treatment into the login slice, and cover public and staff in one bounded
accessibility slice.

The fix shape is already proved by the shell candidate: keep `:focus-visible` for the ordinary
treatment so the approved composition is untouched, and add `:focus` only where the element is
off-screen at rest or where forced-colors mode has discarded the ordinary indicator. That distinction
matters — a blanket `:focus` would change the pointer-interaction appearance of ordinary controls,
which `DESIGN_GUIDE.md` §11 does not sanction.
