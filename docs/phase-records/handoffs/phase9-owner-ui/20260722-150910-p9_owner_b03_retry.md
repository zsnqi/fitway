greatest `(effectiveFrom, version)` not later than that instant. `Asia/Riyadh` is only a default
pending on-site confirmation; never hardcode or fall back to it. Browser timezone is never
authority.

Keep `DailyAnalytics` unchanged. Add owner-only `admin.analytics.timeContext`: strict input
`{ settingsVersions: number[] }` of unique positive safe integers derived from analytics; strict
output `{ current: { settingsVersion, timeZone }, versions: Array<{ settingsVersion, timeZone }> }`.
`current` is effective at server `now`; all requested versions must resolve to valid IANA zones or
the request fails. The optional daily query uses current timezone plus its internal boundary.
Format each bucket/peak with the zone mapped from its own `settingsVersion`.
