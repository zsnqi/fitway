## Scope and decisions

- Implemented only the frozen durable command, transactional audit, edge acknowledgement,
  protocol-parity, and router-lane-A slice. No staff UI, manual fallback, scheduled reset,
  analytics transport, public payload, auth, root configuration, or coordinator ledger change
  is included.
- The durable lifecycle is exactly `pending | applied | superseded`. Delivery is represented by
  nullable `deliveredAt` metadata, not a fourth lifecycle state.
- `set_count` and `reset_zero` are conflicting count-authority commands. Issuing either
  supersedes every older pending command atomically, making the Phase 5 response latest-only
  with at most one effective command.
- The shared command queue owns deliver/ack policy. Occupancy invokes that boundary only after
  accepting a contiguous live push; replay, gap, invalid, and backfill-shaped requests cannot
  mutate command or audit state.
- An acknowledgement applies only a pending command that was previously delivered. Repeated
  acknowledgement is idempotent, and online commands never overwrite cloud current state.
- Human issuance re-checks `staff | owner`, resolves deltas while locking current state, floors
  at zero, and writes the command plus immutable actor/provenance audit row in one transaction.
