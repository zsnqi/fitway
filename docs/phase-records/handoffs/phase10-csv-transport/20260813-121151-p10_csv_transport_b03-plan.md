## Regression-first production contract

Thread the optional request `AbortSignal` through API context and reporting repository. After a
pool client is acquired, register an abort listener and immediately recheck `signal.aborted` to
close the registration race. Use a single idempotent release boundary:

- normal completion closes the cursor if opened, commits the successful read-only transaction, and
  releases the reusable client exactly once;
- consumer early return/error closes the cursor if opened, rolls back, and releases the reusable
  client exactly once;
- abort destroys the client exactly once with `release(true)`, promptly terminating any active
  `BEGIN`, settings read, cursor declaration, or `FETCH` and relying on disconnect rollback;
- after destructive release, do not issue `CLOSE` or `ROLLBACK` on that client;
- remove the listener in `finally` on every path;
- preserve the primary producer/query failure if cleanup or release also fails; cleanup errors may
  surface only when there is no primary failure.

The transport still forwards incrementally, validates every yielded event lazily, and memoizes its
underlying `return()`. Passing the signal to the repository is mandatory; iterator return remains a
consumer-cleanup seam, not the database cancellation mechanism.
