## Finding: new load-sensitive debt on the unit ladder, outside this slice

One red run was **not** a coordinator error and is a genuine finding.

`apps/server/src/reference-gating.test.ts:5` failed with `Hook timed out in 10000ms` inside the full
unit run. The `beforeAll` sets environment variables and `await import("./index")`.

The first hypothesis — that it needed the disposable Postgres, which had **exited at the power loss
three hours earlier** and fit the evidence neatly — was **tested and disproved**: the file passes
standalone in **1.17s with Postgres still down**, importing in 29ms. It needs no live database.

The actual mechanism is load. The failing run's aggregate import time was 30.22s and environment
setup 301.25s; the 10,000 ms hook timeout lost that race. It did not recur on the clean re-run.

Its disposition is genuinely awkward and is therefore escalated rather than absorbed:

- **not a Slice B defect** — the file is `apps/server/**`, and this slice's entire diff is
  `apps/web/**`, `tests/browser/**` and records;
- **the slice may not repair it** — `apps/server/**` is forbidden scope;
- **the slice may not register it** — this milestone explicitly forbids opening a known-flaky
  register entry for a failure its own run hits, and no existing entry covers it.
  `scripts/flaky-attribution-check.mjs` fails closed on anything unrecorded, so the red run is **not**
  being excused by attribution.

This is the same debt class the browser ladder already went through under `phase11-browser-debt` and
`phase11-ladder-contention`, now appearing on the unit ladder. **It belongs to a human decision.**
