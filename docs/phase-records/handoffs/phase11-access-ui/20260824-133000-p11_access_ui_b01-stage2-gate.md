## The two constraints stage 1 bought, and how stage 2 discharged them

**`staff_pin_shape` is not a caller refusal.** The exported `OwnerAccessRefusalCode` union
(`apps/web/src/hooks/use-owner-access.ts:32-40`) is the **nine** owner-provokable codes only, with
the omission documented at the definition. The classifier maps a `BAD_REQUEST` carrying
`staff_pin_shape` to `failed` rather than `refused`, pinned by a test at
`use-owner-access.test.tsx:396-404`. The implementer independently rejected oRPC's `isDefinedError`
because a directly constructed `ORPCError` carries `defined: false` — a detail neither the plan nor
the stage-1 map supplied.

**The revealed PIN never reaches the mutation cache.** TanStack Query retains `mutation.data` after
a mutation settles, so the naive shape would leave credential material cached indefinitely. The
mutation function parses the reveal schema, hands `revealedPin` to hook-local React state that dies
on dismissal or unmount, and returns only a rebuilt three-field object
(`use-owner-access.ts:136-142`, `:175-200`). The test asserts the property against the live mutation
cache and guards itself against passing on an empty cache
(`use-owner-access.test.tsx:441-448`). The negative control above proves it would catch a
regression. Nothing logs a mutation result.

**Stage 4's mount problem was not foreclosed.** `enabled` is a required argument with no mount-time
default; `enabled: false` yields status `standby` and issues zero requests, so the section can gate
on its own prerequisite without any sibling spec needing an `admin.access` stub — which this slice
is forbidden from adding.
