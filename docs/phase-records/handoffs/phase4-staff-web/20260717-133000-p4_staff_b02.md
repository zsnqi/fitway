## Goal and acceptance

Deliver the Phase 4 staff web surface on the integrated real backend: the PIN-first `/login`
route that replaces the nonconforming email/password scaffold, the `/staff` operational view
bound to the integrated `staff.operationalSnapshot`, and the owner-only `/admin` shell stub —
per `SPEC.md` 384–457 and 528–536, `PHASES.md` Phase 4, ADR-002, `DESIGN_GUIDE.md`, and the
approved visual manifest. No scaffold auth behavior may survive.

Binding contract consumption (all read-only; never re-implement or fork):

- Authentication uses the integrated endpoints exactly: `POST /api/auth/staff/pin` (6–12
  Western digits, non-enumerating errors, rate-limit `429` honored in UI), `GET
  /api/auth/session`, `POST /api/auth/logout`. Sign-up remains rejected; no Better Auth
  email/password staff flow, no synthetic staff identity. The session is the httpOnly cookie
  the server issues — the web app never stores tokens.
- `/staff` renders `staff.operationalSnapshot` through the typed oRPC client: the frozen
  ten-field `health` block plus `schemaVersion`, `computedAt`, public occupancy fields,
  authorized `capacity`, and source detail. The UI only renders freshness/condition — it
  never recomputes them, and it never converts a transport/API failure into `unavailable`.
- Route guards are redirect-only UX. `401` → `/login`; `403` renders the localized
  wrong-role state. Server enforcement is the authority; `/admin` accepts only `owner`.

Acceptance requires:

- `/login`: PIN-first form, digits-only input handling, non-enumerating error copy, rate-limit
  handling, loading/disabled states, successful redirect to `/staff`, logout round trip.
- `/staff`: every operational state honestly rendered — loading skeleton, live, stale
  (last-known with its time, never looks live), unavailable, and transport error as a distinct
  error state; private capacity visible only here, never leaked into public surfaces.
- `/admin`: owner-only shell stub with localized navigation placeholder; staff sessions get
  the `403` treatment.
- Scaffold removal: the email/password `SignInForm` and any Better Auth client staff-flow
  usage are deleted, not bypassed.
- Full phase polish loop (`docs/WORKFLOW.md`): deterministic Playwright functional checks in
  Arabic RTL and English LTR; applicable widths from 320, 360, 390, 721, 768, 820, 1024,
  1200, 1440; keyboard order, focus visibility/return, 44px practical targets, reduced
  motion, concise live regions for state changes, screen-reader names, 200% zoom/reflow,
  safe areas, no page overflow; automated accessibility checks plus manual semantics.
- Polish backlog: `VIS-004` is owned by this slice (compact surfaces adapt to content).
  `VIS-001`/`VIS-002` apply only through the shared shell/atmosphere leases and stay
  CSS-only static layers within their recorded acceptance boundaries. `VIS-003` is Phase 6
  and out of scope.
- All copy in the ar/en message catalogs (leased); Western digits via `-u-nu-latn`; bidi
  isolation; no hard-coded strings.

Browser tests are functional and deterministic: mock only at the HTTP boundary using
fixtures that conform byte-for-byte to `operationalSnapshotSchema` and the auth endpoint
contracts — never invent fields, never bind to scaffold shapes. Do not add `toHaveScreenshot`
canonical baselines: curated evidence goes to the run review directory; creating or updating
canonical baselines is a serialized human-approved pass after integration.
