## Objective

Freeze a strict device contract in which reconnecting devices durably buffer completed minute
buckets, send those buckets with explicit history-only authority, apply any pending command before
a live sample can advance current occupancy again, and prove TypeScript, generated OpenAPI, shared
JSON fixtures, Python simulation, and disposable-Postgres behavior agree.

## Confirmed public seams

- `edgePushRequestSchema` / `edgePushResponseSchema` for the device wire contract.
- `processLivePush` and `OccupancyTransaction` for atomic sequence, history, current, health, and
  command reconciliation behavior.
- authenticated `POST /edge/push` for the real HTTP/database vertical slice.
- `generateOpenApiDocument` plus shared JSON fixtures for schema parity.
- the Python simulator's persisted state, request construction, acknowledgement validation, and
  command application behavior.

These are the seams explicitly named by the Phase 6 acceptance contract; tests will not target
private helpers.

## Scope

Write only the milestone-owned paths and the active exclusive edge-spine lease recorded in
`PROJECT_STATE.yaml`. No schema/migration, environment, router/context/server-index, verification
script, ledger, or UI work is permitted. The lease expires at
`2026-08-16T18:30:00+03:00` and must be rechecked before every leased-file edit.

## Stages and rollback boundaries

1. **Contract and authority tracer.** Add one failing schema/domain test for explicit live versus
   backfill requests and command-before-live disposition; implement the smallest strict v2
   contract and pure reconciliation rule. Rollback: revert this additive test/domain/schema stage,
   leaving the Phase 5 v1 contract intact.
2. **Transactional engine tracer.** Add one failing engine test for history-only backfill and one
   for `commands_pending`; implement conditional minute/current/health/sequence writes without a
   schema change. Rollback: revert the engine stage together, returning processing to live-only.
3. **HTTP/Postgres tracer.** Add the owned Phase 6 integration test for outage/reconnect,
   duplicate/gap/replay, command ordering, minute idempotency, and current-state protection; make
   only repository/handler changes required by that public behavior. Rollback: revert the
   integration/repository stage; the contract/engine remain independently unit-tested.
4. **Python/outbox and parity tracer.** Add failing Python tests and shared fixtures for a durable
   48-hour completed-minute buffer, backfill-first reconnect, command application before live,
   and strict acknowledgement validation; implement the simulator behavior and align the OpenAPI
   document/tests. Rollback: revert the Python/fixture/OpenAPI stage; TypeScript semantics remain.
5. **Decision-6 review and closeout.** Record whether any production writer of `source=manual`
   remains, distinguishing retained enum/settings consumers from actual producers. Do not remove
   a database enum or settings field in this slice. Rollback: handoff-only documentation change.

Each stage runs red then green before the next starts. No refactor-only stage is planned.

## Risks, unknowns, and stop conditions

- A request schema version bump is expected because explicit authority is a breaking wire change;
  fixture/OpenAPI/Python parity must prove the final shape atomically.
- Backfill batches must stay below the existing 16 KiB HTTP request cap; the contract will use a
  bounded batch size and the Python client will send repeated batches.
- Existing Phase 5 tests may encode live-before-command behavior. They are read-only to this
  worker and must remain unchanged and pass through compatibility at the exported seam.
- Any required database enum/settings removal, migration, router description change, environment
  addition, or UI becomes `NEEDS_HUMAN`/coordinator escalation.
- The same failing gate receives at most two focused repair attempts; a third recurrence is
  `FAILED_VALIDATION`.
